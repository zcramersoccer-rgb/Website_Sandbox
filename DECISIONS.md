### Two automation traps, both of which nearly caused a wrong request

- **There are two text inputs on the Search Console overview.** The one to drive is
  `aria-label="Inspect any URL in cramerslandscaping.com"`; the other, `aria-label="cramerslandscaping.com"`,
  is the **property selector**. Typing a URL into the property selector silently bounces to the
  overview. Select the box by its aria-label, never by position or visibility — the inspect box
  reports zero width until focused, so a "first visible input" heuristic picks the wrong one.
- **The inspected-URL header contains Private Use Area characters** (Material icon ligature
  codepoints, e.g. 58131 / 58134) concatenated into `textContent`, and renders the URL **twice**
  (parent plus child). A strict equality check against the expected URL therefore fails on a
  perfectly good page. Strip `\uE000-\uF8FF` and whitespace, then take the first URL occurrence.
  Stripping only those ranges cannot turn one real URL into another, so the check stays safe.
- **Do not `await` more than ~40s inside one javascript_tool call** — CDP kills it at 45s with
  "renderer may be frozen". Click, wait ~25s, then poll in a separate call.
- Verification rule unchanged and honoured for all 11: a URL is only `mark`ed after its confirmation
  toast was read from the live DOM with computed-visibility filtering, alongside the header URL it
  was clicked for.
